# RK3588（Orange Pi 5 Ultra）USB3 工业相机问题 —— 完整方案文档

> 基于 Joshua-Riek/linux-rockchip jammy 分支（Linux 5.10.209）
> 目标相机：MindVision SUA133GC（**USB3 Vision 协议，彩色 CMOS，1280×1024**）
> 文档日期：2026-10-05

---

## 一、问题定义与最终定性

**原始症状**：USB3 工业相机接入 Orange Pi 5 Ultra 后 10~276 秒内随机挂起，dmesg 报 `-71 (EPROTO)`，必须重新插拔；USB2 模式稳定；x86 笔记本正常。

**本轮实测定性（重要修正）**：
1. 手头这颗 SUA133GC 是 **USB3 Vision 标准协议相机**（接口子类 5，bulk 控制/流/事件三接口），**不是 UVC 设备**——原始报告中的 `uvcvideo: -71` 不可能来自它（uvcvideo 从不绑定 USB3 Vision 设备），大概率与社区的 Arducam UVC 案例混淆。
2. 板上实测到**平台级 SS 链路不稳**：两颗同型号相机（序列号 …304 / …305）都出现枚举 `-71`、`reset SuperSpeed`、裸挂自发掉线（无驱动、零 I/O 状态下 9~91 分钟内死亡）、掉线后控制通道 `LIBUSB_ERROR_IO` 假死须物理拔插。
3. 掉线瞬间**内核零报错**（无 xHCI 错误事件）——链路静默死亡，指向 usbdp PHY / LFPS / 信号层，而非可打补丁的 USB 软件栈。

## 三、排查矩阵（全部有源码级证据）

| 怀疑方向 | 核查方法 | 结论 |
|---|---|---|
| DTS 缺 DWC3 quirk | Joshua 5.10 vs 原厂 6.1 `rk3588s.dtsi` 逐节点对比 | **完全一致**，排除 |
| xHCI 等时路径缺修复 | 逐函数对比主线 v6.6（process_isoc_td / queue_isoc_tx / handle_tx_event 等 10 个函数） | **函数级一致**，仅多中断器重构，排除 |
| naneng combphy 差异 | 5.10 vs 6.1 全 diff（667 行） | 全是重构 + RK3576 新增，无 RK3588 USB3 功能变化，排除 |
| `dwc3-rockchip.c` glue | 该文件在此树**不存在**；RK3588 由 `dwc3-of-simple.c` 兜底绑定（diff=0 行） | 任务书前提不成立，排除 |
| LKML usbdp reset-notify 系列 | 对照主线 v16 补丁与树内驱动结构 | 针对主线新 glue 架构，无法移植；其修复目标（replug 后 lcpll 超时）与本问题不同源 |
| 原厂内部修复 | Joshua 5.10 vs OPi 6.1 全 USB 子树 diff | **Rockchip 从未修过等时相关代码**（6.1 同样复现，issue #1081 佐证） |
| usbdp PHY 驱动 | 5.10 vendor 版 vs 6.1 主线版 | **有实质差异** → 补丁 0001 |
| DWC3 时序寄存器 | REFCLKPER/GFLADJ 编程 | 5.10 缺失、上游 v5.13 有、6.1 vendor 携带 → 补丁 0002/0003 |
| 端口映射 | 板级 DTS | Ultra/Max 的 USB3 Type-A = `usbdrd_dwc3_1`（host 模式）+ `usbdp_phy1`；原生 host 控制器 `usbhost3_0` 被 disabled |

## 四、内核补丁（分支 `rk3588-usb-isoc-fixes`，共 4 个 commit）

### 0001 `3ef817a02` — usbdp PHY 主线化对齐
`drivers/phy/rockchip/phy-rockchip-usbdp.c`
- 24M/26M 参考时钟表增加 `{0x00D4, 0x30/0x33}`（LCPLL lock/AFC 检测使能，顺序对齐主线）
- 初始化序列增加主线新增的每 lane 微调 `{0x09C0,0x0A} {0x19C0,0x0A}`
- 状态检查：CDR 失锁超时 → 主动禁用 USB3 口（对齐主线 `udphy_status_check`）

### 0002 `7e58f1756` — DWC3 REFCLKPER/GFLADJ
`drivers/usb/dwc3/core.c|core.h`
- 移植上游 v5.13（Sean Anderson/Thinh Nguyen）的 `dwc3_ref_clk_period()`：按参考时钟周期编程 `GUCTL.REFCLKPER`，帧长误差经 `GFLADJ` 修正
- 新增 DT 属性解析 `snps,ref-clock-period-ns` 与 `snps,gfladj-refclk-lpm-sel-quirk`

### 0003 `16b6819fd` — 设备树生效补丁
`rk3588s.dtsi / rk3588.dtsi`：三个 USB3 dwc3 子节点增加 `snps,ref-clock-period-ns = <41>`（24MHz→41ns）

### 0004 `df1637036` — 新增 `rk3588-orangepi-5-ultra.dts`（5.10 树原本没有）
按原厂 Ultra 板级差异：**禁用 HDMI0 全链路**（Ultra 物理口在 HDMI1/vp0，根治幻影屏）；OTG 5V 使能脚 PB3→PB1；LED 极性；风扇 PWM 周期。

> 补丁文件：`F:\Test\patches\0001~0004.patch`（git am 可直接应用）

## 七、相机方案（USB3 Vision 正确路径）

厂商 Linux SDK（V2.1.0.49）实测**不认自己的 SUA133GC**（枚举 -16，strace 证实打开节点后拒绝认领）。改用 **Aravis 0.8.31**（开源 USB3 Vision/GenICam 协议栈，源码构建）：

```
枚举成功：MindVision-042090420305 (USB3)
采流验证：Mono8 1280x1024 @10ms 曝光 → 20 秒 1551 帧 0 错误（~77fps）
```

**实时预览管线**（当前在板上运行）：
```
arv_grab（root：BayerRG8 采集 + 有界队列[≤2帧] + NN 去马赛克 RGB24）
  → ffplay（用户 Wayland 会话窗口，-fflags nobuffer -flags low_delay）
```
- 窗口标题：`MindVision SUA133GC COLOR live (Aravis 1280x1024)`
- 延迟恒定（≤2 帧），撕裂根因（生产 77fps > 消费 60fps 的无界排队）已修

## 九、后续实验矩阵（按信息量排序）

1. ~~**换口对照**~~ **已完成（2026-10-05 晚）**：相机从 Type-A 口（bus6，`fc000000`/usbdrd_dwc3_0+**usbdp_phy0**）换到另一 USB3 口（bus8，`fc400000`/usbdrd_dwc3_1+**usbdp_phy1**）。结果：**两路独立 PHY 均复现掉线**（旧口裸挂与推流皆挂；旧口推流状态下存活约 40 分钟后自发掉线，uptime 12362s 处）→ "单口信号问题"排除，**平台级（RK3588 USB3 主机 ↔ 该相机家族固件）互操作缺陷坐实**。新口验收观察进行中（`/tmp/cam-history-bus8.log`）。
2. **30 分钟流传输验收窗**：预览窗即验收现场；卡死报时间点即可拉现场（usbmon 需 `modprobe usbmon`）。
3. **label old A/B**：原厂内核跑同样裸挂观察，量化补丁内核是改善/持平/变差。
4. **联系 MindVision**（报序列号 042090420305/…304）：索取 SUA 系列在 RK3588 平台的兼容性说明与相机固件更新——两颗相机、两路 PHY 都掉线而 x86 正常，厂商侧可能已有 firmware 修正。
5. 若上述全部排除 → 硬件层：USB3 眼图/示波器测 SS 信号质量。
